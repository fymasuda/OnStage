Princípios de Design — OnStage

O wireframe foi construído com base em padrões de mercado consolidados, combinando elementos de apps que os usuários já conhecem. O objetivo é que qualquer pessoa abra o app e pense "já sei usar isso".

1. Feed estilo Instagram/TikTok

A tela principal é um scroll infinito com cards de músicos (foto, vídeo, música). Ações familiares: curtir, comentar, compartilhar, salvar. O usuário já sabe o que fazer sem tutorial.

2. Busca estilo Spotify/Uber

Explorar usa chips de filtro (gênero, estilo) + busca textual + mapa. O mesmo padrão de apps de streaming e locação. Filtros visuais, resultado imediato.

3. Perfil estilo Instagram

Avatar, bio, estatísticas (shows/seguir/rating), grid de posts. O formato é universal — qualquer rede social usa isso. Músicos já estão acostumados.

4. Chat estilo WhatsApp/iMessage

Lista de conversas com avatar, preview da última mensagem, horário, badge de não lido. O padrão de mensageria é onipresente — zero curva de aprendizado.

5. Agenda estilo Google Calendar/Airbnb

Calendário visual com dias marcados, eventos abaixo. O formato de calendário é universal. O destaque visual para dias com evento é o mesmo padrão de apps de reserva.

6. Bottom Tab Bar (5 ícones)

Início, Explorar, [+] (ação principal), Agenda, Perfil. É o padrão ouro de navegação mobile (Instagram, Twitter, Spotify). O botão central destacado em roxo é a ação primária (postar/contratar).

7. Barra de Créditos

No topo da agenda e perfil, uma barra roxa com saldo de créditos — parecida com gift cards e apps de finanças. Deixa claro o modelo de forma visual e não intrusiva.

Paleta e Tipografia

  • Roxo (#533afd): cor primária, CTAs, logo, destaques
  • Amarelo (#fbbf24): alertas, ratings, badges, crédito
  • Verde (#10b981): confirmação, disponibilidade, preço
  • Vermelho (#ef4444): likes/notificações
  • Inter: fonte principal — clean, moderna, altamente legível em mobile

Próximos Passos

  • Validação: mostrar este wireframe para 5–10 músicos e contratantes. Coletar feedback.
  • Figma: transformar em protótipo interativo de alta fidelidade.
  • Teste de usabilidade: observar pessoas usando o protótipo sem instruções.
  • MVP técnico: implementar as telas 1, 2, 3 e 4 como versão alpha.
  • GitHub Pages: publicar este wireframe online para acesso pelo celular.
